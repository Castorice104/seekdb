## 目标与边界

## 实现路线与取舍

1. 继续扩充当前线程缓冲 + 下一条查询触发：改动较少，但不满足事务边界、异步自主完成和重启恢复，淘汰。
2. 应用脚本或数据库外轮询服务：开发较容易，但违反内核实现要求，淘汰。
3. 数据库内事务型任务表 + 生命周期受管理的后台 worker + 版本化原子发布：推荐；能够满足题面，改动涉及多个内核层，需要真实事务及故障测试。

第三条是满足题面约束的可行路线。这里的具体机制是实施建议，尚未声称用户已经批准。保留现有可复用 DDL 片段及 Mock；用正式实现替换临时线程缓冲路径，变更前保存起始 diff 和未跟踪头文件。

## Schema 与 DDL

- AI 列是可见、可索引的普通物理结果列，增加正式 AI 标记和持久化定义。保存原始/规范化表达式、解析后的依赖列 ID、结果类型与精度/向量维度、max_retries、sync_mode、定义版本及隐藏列映射。
- 使用原生表达式 resolver/AST 检查，顶层只接受 AI_COMPLETE 或 AI_EMBED，校验模型类型、函数参数、向量维度、支持的 SQL 类型及非法选项；拒绝自身/其他 AI 列依赖、子查询和不允许的表达式。常量及 NULL 输入行为沿用已有 AI 函数。
- 解析完整列集合后确定依赖，允许合法依赖声明在后面的普通列。字符大小写、带引号标识符和字符串常量遵循 SQL 规则。
- max_retries 必须是非负且不溢出的整数；选项只接受已定义名称，重复或无效值报错。默认 async 与默认重试值由实现明确并纳入单测；建议默认 max_retries=0。
- 根据结果类型追加独立的系统提示词，保留原始业务输入和用户配置语义；输出仍必须经过严格 SQL 类型/精度、JSON 和向量形状校验，转换失败进入失败重试而不是截断为成功。
- 支持 CREATE、ALTER ADD、SHOW CREATE/SHOW AI COLUMNS；按公开 parser 测试及 Schema 能力支持 MODIFY，定义变化推进版本并使旧任务失效。新增 AI 列为已有行创建待生成任务。
- 隐藏状态/请求版本列按列 ID 关联，避免名称解析猜测；Schema copy、序列化、列 ID 重映射均覆盖。用户 comment 保留原义。
- DDL 元数据写入必须走现有 Schema/DDL 生命周期，避免建表成功后另开事务写定义所造成的半完成状态。DROP/RENAME/MODIFY 同步处理映射与过期任务，不允许旧定义回写。

## 行状态与任务

可见状态为 PENDING、READY、FAILED。NULL 是合法结果的可能值，不能用结果是否 NULL 判断 READY。

每行本次触发的一组 AI 列使用同一 request_id/group_id。每个 AI 列隐藏保存当前请求标识和状态；任务另存 table_id、column_id、定义版本、强类型/安全编码主键、确定的模型输入与配置快照、尝试次数、eligible_ts、owner、领取代次、lease 截止时间、阶段结果及错误。

任务执行状态与用户状态分离。持久化任务支持：待领取 → 执行中 → 延迟重试 / 成功终态 / 失败终态 → 分组发布后清理。内部数值编码遵从已有测试约定，例如其观察到的 state=3/retry_count=1，先核对测试再定义枚举，不将含义散落在代码中。

request_id 使用数据库内可靠唯一 ID 机制，不单靠微秒时钟。主键包括复合、字符串、无显式主键的内部行键；不拼接未经转义的主键 SQL，也不假设只有整数主键。

## DML 与事务

- 计划生成/执行层识别 AI 列，仅 AI 表增加额外维护。INSERT、INSERT SELECT、批量、UPDATE、主键更新、REPLACE/UPSERT 等有效插入/变更路径统一覆盖。
- 在业务事务和语句保存点内，同时完成：业务行变更；受影响结果置 NULL、状态 PENDING、请求版本推进；任务入库；替代或取消旧任务。
- 任务写入复用同一事务描述符，不能开独立自动提交事务，也不能在下一条用户 SQL 前补写。失败即让业务语句按原有事务规则失败。
- 依赖字段真正变化或主键变化触发；无关字段更新不触发。受影响列共享组 ID，未受影响的 AI 列保持原值/状态。
- 先求值输入快照但不调用模型；事务提交后 worker 才能读取任务。ROLLBACK、ROLLBACK TO SAVEPOINT 和语句失败同步撤销任务、失效与索引变化。
- DELETE 在同一事务清理该行任务，已在途请求即使返回也不能恢复行。主键变更清除旧键任务并在新键创建新组。
- 业务显式指定 AI 结果列（包括 INSERT、UPDATE、UPSERT、REPLACE、LOAD DATA 对应路径）报错。后台写回采用受限内部执行上下文，不能仅靠普通会话可伪造的标志绕过。

## 后台执行与恢复

- 使用现有数据库后台线程/服务生命周期注册，不依赖用户发起查询。初始化、启动、停止、取消请求和 join 跟随数据库服务；内存/并发有界。
- 领取短事务：只选已提交且到期任务，原子比较并写 owner、lease 和领取代次；避免两个 worker 同时拥有同一任务。先提交领取事务，再调用 HTTP。
- 调用期间不持有业务行锁或长事务；复用已有 AI provider/client，对超时、429、5xx、断连、错误 JSON、维度和转换失败统一记录可重试结果。
- 初始尝试加 max_retries 次自动重试，指数退避且有上限；阶段结果落库。成功列等待组内其余列终态期间不再次调用模型。最终失败列生成 FAILED 与 NULL。
- 进程崩溃/执行中断后，lease 到期可重新领取；所有完成写入校验 owner 和领取代次，旧 worker 不能发布或删除新领取者的任务。
- 上游完成但响应丢失允许至少一次重试；不声称外部推理恰好一次。若 Endpoint 支持幂等键，可附带稳定请求标识但不得依赖其支持。

## 分组发布与旧结果保护

组内全部列达到成功/失败终态后开启短事务。读取并锁定当前行，按 table/column 身份、当前请求标识、定义版本、worker 领取所有权验证任务归属。任何过期部分不得写回、删除新任务或混入新的请求组。

按确定的列顺序锁定，同一组一次 UPDATE 写入全部结果与 READY/FAILED 状态；向量与索引通过正常 DML 维护。失败列写 NULL，成功列保留成功结果。清理本组任务并同事务提交。发布前崩溃可恢复并重试发布，不重复已持久化的成功推理。

被 UPDATE、RETRY、DELETE 或 DDL 淘汰的组仅清理自身过期任务。所有清理条件包含请求标识和列/定义身份，不能仅按主键删除。

## RETRY 与严格读取

- ALTER TABLE ... RETRY AI COLUMN <单列> [WHERE <表达式>]；不能与其他 ALTER action 混用，普通列或未知列报错。
- WHERE 由原生 resolver 绑定；未加反引号的 status 绑定到目标 AI 列状态，带反引号的 `status` 是业务列。任意主键/普通业务字段条件按正常 SQL 语义执行。
- 可重新生成 READY/PENDING/FAILED 行；仅目标 AI 列、命中的行失效并入队。零行命中不创建任务。重试语句内部的数据失效与入队须原子，遵循 ALTER 的隐式提交边界，但不能把它伪装成普通业务事务内可回滚 DML。
- SESSION ai_column_strict_read 默认 OFF；通过标准系统变量机制声明和生成，适用于文本 SQL、预编译 SQL及缓存计划。
- 收集 SELECT/UPDATE/DELETE 中真实引用的 AI 列（投影、谓词、排序、分组、连接、子查询等）；对每个引用列在当前语句快照下全表检查是否存在非 READY 行。不能下推用户 WHERE 后才检查，也不能仅检查返回行。
- 普通列语句或仅引用其他全 READY 的 AI 列不受影响；未知隐藏状态视为未就绪。严格检查失败在写入前返回既有规范错误（公开测试为 11120），语句不发生部分修改。
- 以语句级快照/现有隔离机制保持检查与读取的一致性，不能使用独立连接读取另一快照。NULL 且 READY 的结果允许严格读取。

## 向量及索引

- AI_EMBED 结果检查维度、有限数值和合法向量类型，使用现有类型转换及索引维护路径。
- 失效时同事务把向量置 NULL，移除旧索引可见项；发布时同事务加入新向量。不能后台直接改存储跳过索引维护。
- 验证 VSAG/HNSW 索引、ANN 查询、依赖更新、RETRY、删除、主键更新、事务及保存点回滚；索引可见性和行数据需遵循其已有一致性约定。

## 验收及顺序

1. 保存现有工作区快照，核实生成代码策略，先建立针对现有缺陷的失败测试。
2. DDL / Schema：接入正式元数据、解析/选项/类型检查、SHOW 和版本变化；补 parser/resolver/schema 原生 C++ 单测。
3. 事务内 DML：移除 thread_local 与查询入口 flush，验证提交前不调用、回滚/保存点无任务、批量和主键/字符串键正确。
4. Worker：领取、并发、重试、阶段结果、分组发布、迟到防覆盖及启动/中断恢复。
5. RETRY / Strict Read：运行已有完整脚本，补预编译、子查询、NULL READY、零行、非法语法及写入拒绝。
6. 向量索引：运行现有向量脚本与回滚/删除/恢复场景。
7. 完整 Release 构建、原生单测、5 个 AI 列 mysqltest，回归 AI 函数增强及文件即数据库；使用独立测试目录和端口。
8. 补专项进程中断恢复、并发 worker、跨端点相同 URL 的全局并发/限流测试。现有公开 Mock 测试通过不等于这些专项通过。

## 审阅前补充：部分组过期与领取粒度

- 调度所有权按 request/group 领取，短事务锁住组内任务并使用同一 owner/领取代次/lease；可在组内并发调用多个列，但不能让互不协调的 worker 分别发布同一组。若使用独立组头记录，其写入与子任务同事务。
- 同一行部分列被后续依赖更新或单列 RETRY 替代时，旧组中这些列标为过期；旧组里仍属于当前请求的其他列继续完成，不被取消、重复调用或长期阻塞。发布只包含仍匹配当前请求及定义的成员，原组所有仍有效成员一起发布。被替代列由新组处理。删除或表定义失效可令整组过期。
- 部分过期检查、有效成员写回和精确旧任务清理在同一发布事务内完成；并发新变更会使发布重试或失配，不允许检查后无条件更新。
- 不修改现有 mysqltest 的预期结果以掩盖功能错误；新增专项测试在相同目录添加明确断言。
